Architecture overview

Factory Inventory Management System

A two-tier demo application: a Vue 3 single-page app talks over REST to a Python FastAPI service, which serves and filters sample data held in memory. There is no database; data is loaded from JSON files when the server starts.

6Routed views (plus 1 unrouted)

Three layers running locally: browser on port 3000, API on port 8001, data on disk.

Data flow

What happens when a user changes a filter, for example selecting a warehouse on the Dashboard.

  1. User changes a filter in FilterBarThe value lands in a module-level ref in useFilters.js. Because the refs live outside the function, every view shares the same filter state (singleton pattern).
  2. The view reacts and refetchesViews watch the filter refs and call getCurrentFilters(), which maps Time Period, Location, Category and Status to month, warehouse, category, status.
  3. api.js builds the requestValues equal to "all" are dropped, the rest become query params, e.g. GET /api/orders?warehouse=Tokyo&month=Q3-2025.
  4. FastAPI filters in memoryapply_filters() does exact warehouse matches and case-insensitive category / status matches. filter_by_month() substring-matches order_date, expanding quarters via QUARTER_MAP.
  5. Pydantic validates the responseEndpoints with a response_model (inventory, orders, demand, backlog) are checked against the model. Summary, spending and report endpoints return plain dicts.
  6. Vue derives what is displayedResponses go into raw refs (allOrders, inventoryItems); KPIs, chart series and tables are computed from them. Currency is formatted per locale (USD or JPY).

Things worth knowing

Client and server are out of sync. api.js defines task and purchase-order calls (POST /tasks, POST /purchase-orders, etc.) that have no backend route and would return 404. Tasks currently live client-side in useAuth.js.
Backlog view is unrouted. views/Backlog.vue exists but is not registered in main.js; backlog data surfaces on the Dashboard instead.
Filters are not uniform. Inventory has no time dimension, so the Time Period filter does not apply to it. Demand, backlog, spending and reports ignore filters entirely.
State is ephemeral. Data is read once at startup; edit the JSON files (and the matching Pydantic models) and restart the server to change it.
